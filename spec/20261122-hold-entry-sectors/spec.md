# 待機の進入セクター（ダイレクト／ティアドロップ／パラレル）

## メタデータ

- **Status**: Done
- **Author**: Kazuki Futawatari
- **Date**: 2026-11-22
- **関連**: [spec/spec.md](../spec.md) フェーズ 3-2、[spec/20261017-terminal-radar-gaps/spec.md](../20261017-terminal-radar-gaps/spec.md)、[spec/20261122-hold-racetrack-overlay/spec.md](../20261122-hold-racetrack-overlay/spec.md)、[spec/20261122-hold-inbound-leg-turns/spec.md](../20261122-hold-inbound-leg-turns/spec.md)
- **リポジトリ配置**: `spec/20261122-hold-entry-sectors/spec.md`

## 概要

#130 で、待機は無風の標準率レーストラックを飛び、指示経路がレーダーに描かれるようになった。ただしフィックスまでの進入は常に直行し、到着後すぐにパターン方向の出方向旋回に入る。本スライスでは、フィックス到着時の針路から AIM の 3 セクター（ダイレクト／ティアドロップ／パラレル）を選び、規程どおりに経路へ合流してから #130 の周回を始める。公示カタログ、EAT／EFC、風修正は範囲外とする。`POST /api/aircraft/{callsign}/hold` は変更しない。位置 API の既存 `holding` オブジェクトへ、進入方式を加算する。

## 背景・課題

### 現状（main `47d5245` で確認）

- Hold 指示 API は入方向・レグ・左右旋回を受け付ける。飛行は無風・標準率（min(3°/秒, バンク 30°)）のレーストラック。位置 DTO の任意 `holding.pattern` をレーダーが琥珀色の破線で描く。
- `HoldPhase.ENTRY` はフィックスへの直行のみ。フィックスを最初に通過した時点で `holdingEntryCompleted` を立て、直ちに `OUTBOUND_TURN` に移る。到着方向による進入の分岐は無い。
- ギャップ台帳と `spec.md` 3-2 の残りは、公示パターン、進入セクター、EAT／EFC、風修正である。README も進入セクターを残課題と書いている。

### 課題（Problem Statement）

- ターミナルレーダーでは、待機指示のあと機体はフィックスへ様々な方向から入る。常に直行して直後に出方向旋回すると、パラレル側から入った機が保護空域の外側を切る、あるいはティアドロップで合流すべきコースを横切るなど、#130 の周回だけでは再現できない進入になる。
- 研究者と管制官がレーダーで見るべきなのは、指示されたレーストラックに、どの進入で合流したかである。

### なぜ今か（Motivation）

- 優先度 1（少ステップで最初のシナリオへ）は #128 で済んでいる。優先度 2 の残ギャップのうち、待機は指示と周回が揃った直後で、進入セクターだけが飛行手順として欠けている。セクターは #130 の非目標に「次の候補」と書いてあった。
- 3 方式は AIM 5-3-8／FAA AIP ENR 1.5 で公開されており、針路と境界を数値テストとブラウザの航跡で検証できる。公示カタログや風、SID／STAR、セクター間ハンドオフより 1 PR に収まりやすい。

## 方針

### 決定方針（Decision）

1. **根拠となる一次資料**
   - **日本（指示側）**: 国土交通省航空局『航空保安業務処理規程 第５管制業務処理規程』（JAPA 2025-03 公開、改正 145、国空制第 591 号、令和 7.3.20 適用）(Ⅱ)６(１)ｂ。待機の指示要素は既に #129 で実装済み。進入方式は同項に書かれていない（パイロット側の飛行方式）。
   - **FAA 飛行側**: AIM [5-3-8 Holding](https://www.faa.gov/air_traffic/publications/atpubs/aim_html/chap5_section_3.html)（公式 HTML）。進入と待機中の旋回は #130 と同じ標準率。進入方式は次の 3 つ（FIG 5-3-4）。保護空域の設計は、パイロットがこの推奨進入に従うことを前提の一部とする。
     - (a) **Parallel**: セクター (a) からフィックスへ近づいたら、非ホールディング側で待機コースに平行な出方向針路へ回り、1 分飛び、待機パターンの方向へ 180° を超えて旋回し、フィックスへ戻るか入方向コースをインターセプトする。
     - (b) **Teardrop**: セクター (b) からなら、フィックスへ入り、ホールディング側で出方向から 30° のティアドロップ針路を 1 分飛び、パターン方向へ旋回して入方向コースをインターセプトする。
     - (c) **Direct**: セクター (c) からなら、フィックスへ直行し、待機パターンに従って旋回する。
     - 非標準（左旋回）も、ホールディング側の 70° 線を基準に同じ向きでセクターを置く。
     - 進入の判定は「フィックス到着時の針路」。セクター境界の ±5° は、パイロットがどちらの進入を選んでもよい運用余裕である。本シミュレータは再現性のため境界を決定論的に割り当て、±5° の任意選択はしない。
   - **FAA AIP ENR 1.5**: [Holding, Approach, and Departure Procedures](https://www.faa.gov/air_traffic/publications/atpubs/aip_html/part2_enr_section_1.5.html)（FIG ENR 1.5-3）。進入用語は AIM 5-3-8 と同じ。DME／距離指定の待機は、時間の代わりに海里を使うほかは同じ進入・待機方式、とする。
   - **FAA 管制側**: Order JO 7110.65BB Change 3（効力 2026-07-09）[4-6 Holding Aircraft](https://www.faa.gov/air_traffic/publications/atpubs/atc_html/chap4_section_6.html)。指示要素は変更しない。進入セクターは管制指示ではなく飛行方式である。
   - **ICAO Doc 8168 (PANS-OPS)**: 国際的な進入方式（オフセット／パラレル／ダイレクト）の出典。本文は有償のため段落番号を置かない。本スライスの定義源は公開されている AIM 5-3-8 と FAA AIP ENR 1.5 とする。
   - 方位は既存どおり測地フレーム（磁偏差なし）。無風のため、フィックスへのコースと到着針路は一致するとして扱う。

2. **セクター幾何（FIG 5-3-4 の 70° 線。テスト用に数値化する）**
   - 入方向コースを `I`、出方向を `O = I+180°` とする。右旋回のホールディング側は、入方向に飛ぶ機体から見て右（方位 `I+90°`）。左旋回はその鏡像。
   - ホールディング側に、出方向コースから 70° の線を引く（AIM の「ホールディング側の 70° 線」）。これで 3 セクターになる。
     - **ティアドロップ**（70°）: 出方向 `O` からホールディング側へ 70° まで。
     - **パラレル**（110°）: 出方向 `O` から非ホールディング側へ 110° まで（入方向から非ホールディング側へ 70° の線まで）。
     - **ダイレクト**（180°）: 残りの半円。
   - 数値例（右旋回、`I = 090°`、`O = 270°`）:
     - ダイレクト: 到着針路 020° から 090° を通り 200° まで（020° は含み、200° は含まない）。
     - ティアドロップ: 200° 以上 270° 未満。
     - パラレル: 270° 以上 020° 未満（北回り）。
   - 左旋回は左右を入れ替える。境界は上記の半開区間に固定する（AIM の ±5° 余裕は実装しない）。
   - 判定に使う針路は、最初のフィックス通過時点の針路（AIM）。フィックス到達前は、現在の針路（無風ではフィックスへのコースに近い）で進入方式を予測してよい。通過時に凍結する。

3. **進入の飛び方（無風、#130 と同じ待機用旋回率）**
   - フィックス到着までは現行どおりフィックスへ向かう。
   - **ダイレクト**: 現行 #130 どおり、フィックス通過後にパターン方向の出方向旋回へ入り、レーストラックを開始する。既存の周回テストは、ダイレクトになる針路で置けばそのまま通る。
   - **ティアドロップ**: フィックス通過後、出方向からホールディング側へ 30° の針路へ旋回する（右旋回: `O-30°`、左旋回: `O+30°`）。時間指定の待機ではその針路を **1.00 分** 飛ぶ（AIM の進入用語は 1 分）。距離指定の待機では、指示された出方向海里だけ飛ぶ（FAA AIP の「時間の代わりに距離」）。その後、パターン方向へ旋回して入方向コースをインターセプトし、フィックスへ入る。2 回目のフィックス通過から #130 のレーストラック（出方向旋回）を始める。
   - **パラレル**: フィックス通過後、非ホールディング側で出方向針路 `O` へ回る（この最初の旋回はパターンと逆方向になる）。ティアドロップと同じ長さ（1.00 分、または指示海里）を出方向に飛ぶ。その後、**ホールディング側へ 180° 超** 旋回し、入方向コースをインターセプトするかフィックスへ戻る（右旋回パターンでは、典型的には左へ 180° 超。AIM 本文の “in the direction of the holding pattern” は、FIG 5-3-4 の「保護側へ戻って入方向を取る」経路として実装する。非保護側へ広がる右回りの大回りにはしない）。2 回目のフィックス通過から #130 のレーストラックを始める。
   - フィックス通過後の進入旋回と、その後の周回は、#130 の待機用旋回率を使う。

4. **API（加算のみ。既存契約を壊さない）**
   - `POST /api/aircraft/{callsign}/hold` はフィールドも省略時互換も変えない。
   - 位置 DTO の既存 `holding` に、任意フィールドを加算する。
     - `entryProcedure`: `"DIRECT"` / `"TEARDROP"` / `"PARALLEL"`。フィックス到達前は予測値、通過後は凍結値。非待機では `holding` 自体が省略される（現行どおり）。
     - 既存の `pattern`（レーストラック頂点）と他フィールドの意味は変えない。
   - 進入の航跡を描く追加頂点（例: `entryPath`）を出すなら任意・加算に限る。Must は `entryProcedure` と、レーダー上の進入方式の可視表示（後述）である。
   - `UranosAPI.yml` と契約テストを更新する。Frontend の `HoldingPatternDto`（`Frontend/utility/aircraft/holdingPattern.ts`）を更新する。トップレベルの位置 DTO キーは増えない。

5. **レーダー**
   - 既存のレーストラックオーバーレイは維持する。
   - Controller と Operator のレーダーで、待機機に進入方式が見えるようにする（レーストラック近くの短い表示、例: `DIR` / `TDP` / `PAR`、または進入経路の破線）。ラベルドラッグ、`HLD`、既存 `pattern` の色・線種は変えない。
   - Resume 後は現行どおり `holding` が消え、進入表示も消える。

6. **テストで固定する数値（製品コードを呼ぶ）**
   - 右旋回・入方向 090° のセクター判定: 針路 090° → DIRECT、200° → TEARDROP、270° → PARALLEL、019° → DIRECT、020° → DIRECT、199° → DIRECT。左旋回は鏡像。
   - ティアドロップ（右、`I=090°`）: 出方向ティアドロップ針路は 240°（270-30）。1.00 分・180 kt なら 3.00 NM。その後、右旋回で入方向 090° をインターセプトする。
   - パラレル（右、`I=090°`）: 非ホールディング側の出方向針路 270° を飛び、ホールディング側（この場合は左回り）へ 180° 超旋回して入方向へ戻る。最初の出方向レグ中、機体はホールディング側ではなく非ホールディング側にいる。
   - ダイレクトでは、フィックス通過後に #130 と同じ出方向旋回が始まる。
   - 許容差は距離 0.05 NM、方位 1°、針路 2°。

### 検討した他案（Alternatives Considered）

- **案 A: 使用滑走路／ATIS の表示スライス（風なし）を先にする。** 採用しなかった理由: `JOIN FINAL` は既に滑走路を明示する。風モデルが無い ATIS は静的な読み上げに近く、待機手順の残ギャップ（進入）より研究上の急ぎが弱い。
- **案 B: リーダー線の自動配置を先にする。** 採用しなかった理由: 1 PR で画面は整うが、ラベルは既に手動ドラッグできる。管制手順の再現ではない。
- **案 C: SID／STAR を先にする。** 採用しなかった理由: 公示手続きのカタログと制約が必要で、1 PR を超える。
- **案 D: セクター間ハンドオフを先にする。** 採用しなかった理由: タワー移管は実装済み。席間・セクター間は複数セクターの前提が要り、アーキテクチャが大きい。
- **案 E: 公示待機（AS PUBLISHED）を先にする。** 採用しなかった理由: AIP カタログ整備が先になり、進入方式が無いと公示経路へ「どう入るか」も検証しにくい。

### トレードオフ（Trade-offs）

- **メリット**: #129–#130 の待機が、到着方向まで含めて規程の推奨進入で見える。ダイレクト以外の航跡がレーダーとテストで区別できる。
- **デメリット / 受容する制約**: ±5° の任意選択はしない。風が無いのでインターセプトは無風幾何。進入レグの「1 分」は AIM の進入用語に合わせ、高度による 1.5 分は進入レグには使わない（周回レグの既定は #129 のまま）。25° FD バンク、待機速度制限、公示パターンは入れない。

### 非目標（Non-goals）

- 公示待機カタログと `AS PUBLISHED`
- EAT／EFC／遅延時間未定
- 風修正、磁偏差、TAS 換算、インバウンド時間の事後調整
- セクター境界の ±5° をユーザーが選ぶ UI
- Hold 指示 API の変更、Controller からの Hold
- SID／STAR、使用滑走路・ATIS・風モデル、セクター間ハンドオフ、リーダー線の自動配置

## 未解決事項（Unresolved Questions）

- 入方向コースのインターセプト: 実装は横偏差 ≤ 0.5 NM（`HOLD_INTERCEPT_XTK_NM`）かつ針路が入方向に収束（`HOLD_HEADING_CAPTURE_DEG`）。パラレルの戻りは 180° 超の連続旋回のあと軸捕捉、その後最短旋回で針路キャプチャ。
- 距離指定待機の進入レグは指示海里（FAA AIP の「時間の代わりに距離」）。時間指定の進入レグは常に 1.00 分（周回レグ分とは独立）。
